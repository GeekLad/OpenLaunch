# Requirements: OpenLaunch

**Defined:** 2026-05-23
**Core Value:** Users can launch a token with a liquidity pool in a single guided flow, without writing code or manually building transactions.

## v1 Requirements

### Launch Parameters — Core

- [x] **LAUN-01**: User can set total token supply (default: 1,000,000,000) — ✓ validated Phase 2
- [x] **LAUN-02**: User can set initial price (default: 0.00001) — ✓ validated Phase 2 (later converted to market cap in Phase 5.1)
- [x] **LAUN-03**: User can set price range minimum (default: 0.000001) — ✓ validated Phase 2
- [x] **LAUN-04**: User can set price range maximum (default: 0.0001) — ✓ validated Phase 2
- [x] **LAUN-05**: Validation ensures min price < initial price < max price — ✓ validated Phase 2

### Launch Parameters — Advanced

- [x] **LAUN-06**: User can set token holdback percentage via slider (default: 0%, max: 100%) — ✓ validated Phase 3 (later inverted to "Locked Liquidity" in Phase 5.1)
- [x] **LAUN-07**: UI shows red-flag warning when holdback > 10% — ✓ validated Phase 3 (warning threshold inverted to <90% in Phase 5.1)
- [x] **LAUN-08**: Holdback tokens are sent to the creator's wallet; remaining supply goes to the pool — ✓ validated Phase 4
- [x] **LAUN-09**: User can select quote token: SOL (default) or USDC — ✓ validated Phase 3
- [x] **LAUN-10**: Price math correctly handles SOL (9 decimals) and USDC (6 decimals) — ✓ validated Phase 4

### Fee Configuration

- [x] **FEE-01**: User can select fee scheduler mode: Market-Cap Based (default), Time-Based, or Disabled — ✓ validated Phase 3
- [x] **FEE-02**: When Market-Cap Based is selected, user can configure starting market cap and ending market cap — ✓ validated Phase 3
- [x] **FEE-03**: When Time-Based is selected, user can configure fee start rate, fee end rate, and total duration — ✓ validated Phase 3
- [x] **FEE-04**: When Disabled, user can configure a fixed base fee (in basis points) — ✓ validated Phase 3
- [x] **FEE-05**: User can select fee token mode: Quote Token Only (default) or Both Quote + Base Token — ✓ validated Phase 3
- [x] **FEE-06**: Fee token mode selection is correctly passed to Meteora SDK `CollectFeeMode` — ✓ validated Phase 4

### Form UI

- [x] **FORM-01**: Default launch form shows only essential fields (name, symbol, logo, description) — ✓ validated Phase 2
- [x] **FORM-02**: All configurable parameters (LAUN-01 through FEE-06) are grouped in an "Advanced Options" collapsible section — ✓ validated Phase 2
- [x] **FORM-03**: Advanced Options section can be expanded/collapsed without losing form state — ✓ validated Phase 2
- [x] **FORM-04**: Form pre-fills all advanced fields with current environment defaults — ✓ validated Phase 2
- [x] **FORM-05**: Red-flag warnings (e.g., holdback >10%) are visible even when Advanced Options is collapsed — ✓ validated Phase 3
- [x] **FORM-06**: Launch confirmation modal highlights any non-default advanced selections — ✓ validated Phase 3

### Validation & Safety

- [x] **VALID-01**: Frontend Zod schema validates all user inputs with human-friendly error messages — ✓ validated Phase 2
- [x] **VALID-02**: Server-side validation enforces SDK-specific constraints (e.g., fee rates, liquidity percentages) — ✓ validated Phase 3
- [x] **VALID-03**: Pre-flight transaction simulation runs before submitting on-chain transactions — ✓ validated Phase 4
- [x] **VALID-04**: If pool creation simulation fails, mint/setup transactions are not submitted — ✓ validated Phase 5

### Persistence

- [x] **PERS-01**: Database schema extended to store all configurable launch parameters per token — ✓ validated Phase 1
- [x] **PERS-02**: Token detail page displays stored launch parameters (holdback %, fee scheduler mode, quote token, fee token mode) — ✓ validated Phase 5
- [x] **PERS-03**: Existing tokens in database remain compatible (nullable columns or sensible defaults) — ✓ validated Phase 1

### Background Jobs

- [x] **CRON-01**: Fee updater cron job reads `collectFeeMode` from database — ✓ validated Phase 6
- [x] **CRON-02**: Fee updater correctly handles quote-only fee tracking (current behavior preserved) — ✓ validated Phase 6
- [x] **CRON-03**: Fee updater supports both-token fee tracking when `collectFeeMode` is "both" (deferred if not feasible in v1) — ✓ validated Phase 6 (per-side split deferred per v1 acceptance text)

## Out of Scope

| Feature | Reason |
|---------|--------|
| Real-time market cap calculation in launch tx | Meteora handles this on-chain via fee scheduler behavior |
| Custom fee scheduler curves beyond Meteora SDK options | Stay within SDK-supported modes for v1 |
| Mobile app | Web-first; mobile later if product validates |
| Multi-chain support (Ethereum, etc.) | Solana-only focus for v1 |
| On-chain vesting contracts | Requires significant smart contract work; defer to v2 |
