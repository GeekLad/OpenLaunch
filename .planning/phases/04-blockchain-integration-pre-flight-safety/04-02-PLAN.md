# Plan 04-02: Wire Fee Scheduler Modes and CollectFeeMode

## Objective

Map the user's `FeeSchedulerConfig` discriminated union to the correct Meteora SDK constructor (`getFeeMarketCapSchedulerParams` or `getFeeTimeSchedulerParams`), pass `feeTokenMode` through to `CollectFeeMode`, and add the `decayMode` sub-field to the market-cap-based branch.

---

## Tasks

### Task 1: Add `decayMode` to `FeeSchedulerConfig` and `CreatePoolParams`

**`<read_first>`**
- `types/fee.ts` (discriminated union definition)
- `types/token.ts` (uses `FeeSchedulerConfig` in `TokenFormData`)
- `lib/solana/poolUtils.ts` (`CreatePoolParams` interface, lines 54–75)
- `.planning/phases/04-blockchain-integration-pre-flight-safety/04-CONTEXT.md` (D-09 through D-14)

**`<action>`**
1. In `types/fee.ts`, extend the `market-cap-based` branch of `FeeSchedulerConfig` to include an optional `decayMode?: 'linear' | 'exponential'` (default `'exponential'`).
2. In `types/fee.ts`, verify `CollectFeeMode` is already defined; if not, add:
   ```typescript
   export const CollectFeeMode = {
     OnlyB: 1,
     BothToken: 0,
   } as const;
   ```
   (or confirm the SDK import is used).
3. In `lib/solana/poolUtils.ts`, add to `CreatePoolParams`:
   - `feeSchedulerConfig?: FeeSchedulerConfig` (import from `@/types/fee`)
   - `collectFeeMode?: CollectFeeMode` (import from SDK)
   - Remove the legacy `feeSchedule?: { enabled, startRate, endRate, decayDuration }` parameter, or mark it deprecated and redirect to `feeSchedulerConfig`.

**`<acceptance_criteria>`**
- `types/fee.ts` compiles — `npx tsc --noEmit` shows zero errors
- `grep "decayMode" types/fee.ts` returns the new field
- `grep "feeSchedulerConfig" lib/solana/poolUtils.ts` returns the new parameter in `CreatePoolParams`
- `npm run lint` passes

### Task 2: Implement fee scheduler mapping in `poolUtils.ts`

**`<read_first>`**
- `lib/solana/poolUtils.ts` (lines 180–247, existing fee configuration block)
- `.planning/phases/04-blockchain-integration-pre-flight-safety/04-RESEARCH.md` (Section 4: Fee Scheduler Mode Mapping)
- `config/defaults.ts` (`DEFAULT_NUMBER_OF_PERIODS`)

**`<action>`**
1. Replace the existing `if (feeSchedule?.enabled)` block (lines 184–247) with a new branch based on `feeSchedulerConfig`:
   - If `feeSchedulerConfig.mode === 'market-cap-based'`:
     - Compute `priceMultiple = Math.pow(endingMarketCap / startingMarketCap, 1 / numberOfPeriod)`
     - Set `baseFeeMode = decayMode === 'linear' ? BaseFeeMode.FeeMarketCapSchedulerLinear : BaseFeeMode.FeeMarketCapSchedulerExponential`
     - Call `getFeeMarketCapSchedulerParams(startBps, endBps, baseFeeMode, numberOfPeriod, priceMultiple, schedulerExpirationDuration)` where `schedulerExpirationDuration = 365 * 24 * 60 * 60` (fixed 1-year default)
   - If `feeSchedulerConfig.mode === 'time-based'`:
     - Call `getFeeTimeSchedulerParams(startBps, endBps, BaseFeeMode.FeeTimeSchedulerExponential, numberOfPeriods, durationSeconds)` — same as current logic but using user inputs
   - If `feeSchedulerConfig.mode === 'fixed'`:
     - Call `getFeeTimeSchedulerParams(fixedBps, fixedBps, BaseFeeMode.FeeTimeSchedulerLinear, 0, 0)` — same as current fixed branch
2. Pass `collectFeeMode` parameter through to `cpAmm.createCustomPool` (line 290), replacing the hardcoded `CollectFeeMode.OnlyB`.
3. Import `getFeeMarketCapSchedulerParams` at the top of `poolUtils.ts` if not already imported (verify existing imports).
4. In `launchService.ts`, update the `createDAMMv2Pool` call sites (lines 213–226, 278–291, 425–438) to pass `feeSchedulerConfig: formData.feeSchedulerConfig` and `collectFeeMode: formData.feeTokenMode === 'both' ? CollectFeeMode.BothToken : CollectFeeMode.OnlyB`.

**`<acceptance_criteria>`**
- `grep "getFeeMarketCapSchedulerParams" lib/solana/poolUtils.ts` shows a call with all 6 arguments
- `grep "CollectFeeMode.OnlyB" lib/solana/poolUtils.ts` returns only the import or parameter default, not a hardcoded usage in `createCustomPool`
- `grep "feeSchedulerConfig" lib/services/launchService.ts` shows it being passed to `createDAMMv2Pool`
- `npm run lint` passes
- `npx tsc --noEmit` compiles with zero errors
