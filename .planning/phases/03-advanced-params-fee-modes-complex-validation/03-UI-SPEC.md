# Phase 03 — UI Design Contract

> Visual and interaction contract for Phase 3: Advanced Parameters, Fee Modes & Complex Validation. Extends Phase 2 patterns. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | manual shadcn-style (no components.json) |
| Preset | not applicable |
| Component library | custom forwardRef primitives in `components/ui/` |
| Icon library | lucide-react 0.553.0 |
| Font | system-ui / sans-serif (Tailwind default) |

**Inheritance from Phase 2:** All spacing, typography, and color tokens from Phase 2 UI-SPEC.md carry forward unchanged. This contract defines only what is new or different for Phase 3.

**New primitives needed:** `@radix-ui/react-slider`, `@radix-ui/react-select`, `@radix-ui/react-dialog`, `@radix-ui/react-alert-dialog`, `@radix-ui/react-radio-group` — installed via npm, custom wrappers in `components/ui/`. (Phase 2 UI-SPEC.md: no new primitives)

## Spacing Scale

**Inherited from Phase 2** — all existing tokens unchanged:

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, inline padding |
| sm | 8px | Tight element groups (label-to-input), inline spacing |
| md | 16px | Default field spacing (`space-y-4`), card internal padding |
| lg | 24px | Section breaks (`space-y-6`), card-to-card gaps |
| xl | 32px | Major layout gaps |
| 2xl | 48px | Page-section separation |
| 3xl | 64px | Page-level vertical rhythm |

**New exceptions for Phase 3:**
- **Slider track vertical padding**: `py-4` (16px) — slider thumb is 20px tall; track needs breathing room (inherited Radix default)
- **Dialog internal padding**: `p-6` (24px) for dialog content area; `p-4` (16px) for dialog header/footer (modal comfort zones)
- **Alert banner padding**: `p-4` (16px) horizontal, `py-3` (12px) vertical — slightly more compact than card content padding for inline alert feel
- **Radio group item gap**: `space-y-2` (8px) between radio buttons in the fee token mode selector

## Color

**Inherited from Phase 2** — all existing tokens unchanged:

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `hsl(var(--background))` | Page background, input backgrounds |
| Secondary (30%) | `hsl(var(--card))` / `hsl(var(--secondary))` | Form section cards, card headers, secondary surfaces |
| Accent (10%) | `hsl(var(--primary))` — light: `216 100% 33%` | Primary CTA button, focus rings, active nav links |
| Destructive | `hsl(var(--destructive))` — light: `0 84.2% 60.2%` | Error text, Custom CA card border |

**Accent reserved for** (extended from Phase 2 — same rules):
- "Launch Token" submit button (`bg-primary text-primary-foreground`)
- Focus-visible ring on inputs and buttons (`focus-visible:ring-ring`)
- Active/hover navigation links (`hover:text-primary`)

**New color usages for Phase 3:**

| Element | Color | Source |
|---------|-------|--------|
| Holdback slider `>10%` badge (collapsed header) | `bg-red-100 text-red-800` (light) / `bg-red-900/30 text-red-400` (dark) | Destructive semantic at 10% opacity — must be immediately visible without overwhelming the layout |
| Red-flag warning banner (expanded section) | `variant="destructive"` on Alert component → maps to `bg-destructive/15 text-destructive border-l-4 border-destructive` | Uses Alert component's built-in destructive variant; do NOT manually override colors — let Alert handle contrast |
| Modal "non-default" value text | `text-red-600` (light-only) / `text-destructive` (semantic, dark aware) | Per D-27 — non-default selections highlighted in red for launch confirmation |
| Slide track fill (left of thumb) | `bg-primary` | Uses accent color to show "selected/active" portion of the range |
| Slide track background (right of thumb) | `bg-secondary` | Uses secondary color for inactive portion |

**Warning banner contrast note:** The Alert `variant="destructive"` ensures proper text contrast against the muted background. Do NOT override with custom background colors (e.g., `bg-red-50`) — the shadcn Alert component is already designed for accessibility.

## Interaction Contract

### 1. Holdback Slider (New Component)

| Property | Value |
|----------|-------|
| Component | `@radix-ui/react-slider` with `cn()` wrapper in `components/ui/slider.tsx` |
| Range | 0–100 |
| Step | 1 |
| Default value | 0 |
| Numeric readout | Rendered to the right of the slider: bold text showing current value + "%" suffix (e.g., "**33%**") |
| `name` | `holdbackPercentage` (registered in react-hook-form) |

| State | Behavior |
|-------|----------|
| Value ≤ 10% | Normal appearance: default slider colors, no badge, no alert |
| Value > 10% | **Expanded state**: Alert banner appears below slider with `variant="destructive"` and AlertTriangle icon. **Collapsed state**: Red badge appears on section header next to title. |

### 2. Fee Scheduler Mode Selection (New Component)

| Property | Value |
|----------|-------|
| Component | `@radix-ui/react-select` with `cn()` wrapper |
| Default | "Market-Cap Based" |
| Options | Market-Cap Based, Time-Based, Disabled (Fixed Fee) |
| `name` | `feeSchedulerMode` |

| Selected Mode | Visible Sub-Fields (CSS `hidden` applied to others) |
|---------------|--------------------------------------------------|
| Market-Cap Based | `feeMarketCapStart` (number input), `feeMarketCapEnd` (number input) |
| Time-Based | `feeStartRate` (number, bps), `feeEndRate` (number, bps), `feeDurationHours` (number) |
| Disabled (Fixed Fee) | `feeFixedRate` (number, bps) |

| Constraint | Enforcement |
|------------|-------------|
| Sub-field switching | `shouldUnregister: false` on parent `useForm` → hidden fields retain values. Use CSS `hidden` class, not conditional render. |
| Value persistence | When switching from Market-Cap → Time-Based and back, previously-entered market-cap values are restored. |

### 3. Fee Token Mode Selection (New Component)

| Property | Value |
|----------|-------|
| Component | `@radix-ui/react-radio-group` with `cn()` wrapper |
| Default | "Quote Token Only" |
| Layout | Vertical stack (`space-y-2`) with radio circles left of labels |
| `name` | `feeTokenMode` |
| Options | Quote Token Only, Both Quote + Base Token |

### 4. Quote Token Selection (New Component)

| Property | Value |
|----------|-------|
| Component | `@radix-ui/react-select` with `cn()` wrapper (reuse same Select primitive as fee scheduler) |
| Default | "SOL" |
| Options | SOL (mint: So111...) with "9 decimals" helper text; USDC (mint: EPjFW...) with "6 decimals" helper text |
| `name` | `quoteTokenMint` |

### 5. Launch Confirmation Modal (New Component)

| Property | Value |
|----------|-------|
| Component | `@radix-ui/react-dialog` with `cn()` wrapper |
| Trigger | When user clicks "Launch Token" button **and** form passes validation |
| Close on `Escape` | Yes (standard Dialog behavior) |
| Close on overlay click | Yes (standard Dialog behavior) |

| Modal Content Structure | Description |
|-------------------------|---------------|
| DialogHeader | Title "Launch Confirmation" + description "Review your launch settings below. Launching a token on-chain is irreversible." |
| Content body | Grouped key-value list. Group headings: "Token Information", "Launch Parameters", "Fee Configuration". Each group shows fields that differ from `DEFAULT_LAUNCH_PARAMS`. |
| Value highlighting | Non-default values displayed in `text-red-600` (light) / `text-destructive` (dark). Default values displayed in normal body text color. |
| DialogFooter | Cancel button (secondary/ghost) + "Launch Token" button (primary accent) |

### 6. Red-Flag Warning Visibility (Two-State Pattern) — REQUIRED PER FORM-05

| Section State | Warning Display |
|---------------|-----------------|
| **Collapsed** | Red badge on section header: `bg-red-100 text-red-800 text-xs` with "⚠ High Holdback" text. Badge MUST be visible without clicking to expand. |
| **Expanded** | Alert banner inside section: `Alert variant="destructive"` with AlertTriangle icon + message "Holding back more than 10% may be seen as a red flag by traders". |
| Transition | When section collapses, expanded Alert disappears and header Badge appears (vice versa when expanding). |

### 7. Validation Behavior (Extended from Phase 2)

| Property | Value |
|----------|-------|
| Trigger mode | `onBlur` (inherited from Phase 2) |
| New cross-field checks | Holdback percentage 0–100; fee rates within 1–9900 bps; market-cap start < end; fee duration > 0 |
| New mechanism | Client-side Zod `superRefine`. Server-side via `POST /api/tokens/validate` (Phase 3, not Phase 2). |
| Error display | Same as Phase 2: `text-destructive` below the relevant field or via Alert for section-level warnings. |
