# Plan 03-03: Dynamic Sub-Fields, Fee Token Mode, Launch Confirmation Modal

## Objective

Complete the form with:
1. **Dynamic fee scheduler sub-fields** — show/hide inputs based on selected mode (Market-Cap / Time-Based / Fixed), with CSS `hidden` to preserve values across mode switches
2. **Fee token mode RadioGroup** — Quote Token Only (default) or Both Quote + Base Token
3. **Launch confirmation modal** — Dialog that appears on submit, showing all non-default selections highlighted in red, grouped by section

## Background

Phase 2 established the `shouldUnregister: false` + CSS `hidden` pattern for collapsible sections. This must be reused for mode-specific sub-fields that need to persist values when hidden.

The `FeeSchedulerConfig` discriminated union in `types/fee.ts` already exists:
```typescript
type FeeSchedulerConfig =
  | { mode: 'market-cap-based'; startingMarketCap: number; endingMarketCap: number }
  | { mode: 'time-based'; startRate: number; endRate: number; durationMinutes: number }
  | { mode: 'fixed'; baseFeeBps: number };
```

Phase 3 CONTEXT.md decisions:
- D-09–D-14: Dynamic sub-fields with CSS `hidden` (NOT conditional rendering) per mode
- D-19–D-21: Fee token mode radio group
- D-26–D-29: Launch confirmation modal with grouped non-defaults in red

### Task 5: Build launch confirmation modal

```xml
<task>
  <id>03-03-05</id>
  <description>Create Dialog modal that appears on form submit, showing non-default values grouped by section</description>
  <read_first>
    - components/ui/dialog.tsx (Dialog compound components)
    - components/forms/TokenLaunchForm.tsx (submit flow, watch() values)
    - config/defaults.ts (DEFAULT_LAUNCH_PARAMS — comparison baseline)
    - 03-UI-SPEC.md (Modal section: group headings, value highlighting, copy)
  </read_first>
  <action>
    Modify the form submit flow in TokenLaunchForm.tsx:
    
    1. Add `const [showConfirmModal, setShowConfirmModal] = useState(false)` to local state.
    
    2. On "Launch Token" click (before actual submission):
       - If form is valid, call setShowConfirmModal(true) instead of directly calling onSubmit
       - If form is invalid, let react-hook-form show errors as usual (blur-triggered from Phase 2)
    
    3. In the Dialog (conditional on showConfirmModal):
       - DialogContent with max-w-lg and standard padding
       - DialogHeader: title "Launch Confirmation", description "Review your launch settings below. Launching a token on-chain is irreversible."
       - Body: iterate over form values from getValues() and compare to DEFAULT_LAUNCH_PARAMS
       - Group non-default fields into:
         - "Token Information" (name, symbol, logo, description)
         - "Launch Parameters" (supply, price range, holdback, quote token)
         - "Fee Configuration" (fee scheduler mode, fee rates, fee token mode)
       - For each field that differs from default: show label in normal text, value in `text-red-600` (light) / `text-destructive` (dark)
       - For default values: show in normal muted text or omit (decision: omit defaults to keep modal clean; show ONLY non-defaults)
       - If NO fields differ from defaults: show a reassuring message like "All settings are at default values."
       
    4. DialogFooter:
       - Left/Cancel: Button variant="outline" onClick={() => setShowConfirmModal(false)}
       - Right/Confirm: Button variant="default" (primary accent) onClick={() => { setShowConfirmModal(false); handleFormSubmit(getValues()); }}
       
    5. The Dialog uses standard Radix behavior: Escape key closes, overlay click closes.
  </action>
  <acceptance_criteria>
    - Clicking "Launch Token" with valid form opens Dialog modal (does NOT immediately submit)
    - Dialog shows grouped list of non-default settings
    - Non-default values are displayed in red text (text-red-600 / text-destructive)
    - Dialog includes exact copy: "Review your launch settings below. Launching a token on-chain is irreversible."
    - If all values are default, modal shows a reassuring message instead of empty list
    - Cancel button closes modal without submission
    - Confirm button proceeds to actual on-chain submission
    - Escape key and overlay click close the modal
    - Modal uses max-w-lg (512px) width
    - Footer buttons are responsive (stack on mobile, row on desktop)
  </acceptance_criteria>
</task>
```

## must_haves

1. Dynamic sub-fields MUST use CSS `hidden` class, NOT conditional rendering (`{isMarketCap && ...}`), to prevent value loss on mode switches.
2. Modal MUST intercept submit — user must see the modal before on-chain action.
3. Only NON-DEFAULT values should be highlighted in red; default values should not appear in the modal (or appear in muted text).
