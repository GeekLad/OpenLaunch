# Plan 03-05: Phase 3 Gap Closure — Fix UAT Issues

## Objective

Address all three UAT gaps identified in `03-UAT.md` so that the Fee Scheduler section uses correct BPS units, displays cross-field validation errors immediately without requiring all required fields first, and enables the Launch Token button when the form is valid.

These gaps share a single root cause: `DEFAULT_FEE_END_RATE` is set to `0.25` (percent) instead of `25` (basis points), which simultaneously (a) displays the wrong unit to users, (b) violates the Zod schema `min(1)` constraint and permanently disables the submit button, and (c) was never paired with market-cap fee rate defaults or inputs. The fix is a targeted surgical update to defaults and form wiring, plus replication of the proven Phase 2 `priceError` bypass pattern for fee scheduler cross-field validation.

       const watchedEndingMarketCap = watch("endingMarketCap");
       const watchedFeeStartRate = watch("feeStartRate");
       const watchedFeeEndRate = watch("feeEndRate");
       const watchedFeeMarketCapStartRate = watch("feeMarketCapStartRate");

    **Step B — Create `feeSchedulerError` useMemo**
    1. Insert immediately after the `priceError` useMemo block (after line 217):
       ```ts
       const feeSchedulerError = useMemo(() => {
         // Market-cap-based mode checks
         if (watchedFeeMode === 'market-cap-based') {
           if ((watchedEndingMarketCap ?? 0) <= (watchedStartingMarketCap ?? 0)) {
             return { field: "endingMarketCap", message: "Ending market cap must be greater than starting market cap" };
           }
           if ((watchedFeeMarketCapEndRate ?? 0) > (watchedFeeMarketCapStartRate ?? 0)) {
             return { field: "feeMarketCapEndRate", message: "Ending fee rate must be less than or equal to starting fee rate" };
           }
         }
         // Time-based mode checks
         if (watchedFeeMode === 'time-based') {
           if ((watchedFeeEndRate ?? 0) > (watchedFeeStartRate ?? 0)) {
             return { field: "feeEndRate", message: "Fee end rate must be less than or equal to fee start rate" };
           }
         }
         return null;
       }, [watchedFeeMode, watchedStartingMarketCap, watchedEndingMarketCap, watchedFeeStartRate, watchedFeeEndRate, watchedFeeMarketCapStartRate, watchedFeeMarketCapEndRate]);
       ```
       > **Rationale:** In time-based mode, fees *decrease* over time, so `feeEndRate` must be ≤ `feeStartRate`. In market-cap-based mode, fees *decrease* as market cap grows, so `feeMarketCapEndRate` must be ≤ `feeMarketCapStartRate`. The `?? 0` nullish coalescing ensures the check runs even when fields are empty.

    **Step C — Display errors inline in JSX**
    1. In the **market-cap-based** sub-fields container (after the `endingMarketCap` input, around line 795–798), add:

       ```tsx

         <p className="text-sm text-destructive">{feeSchedulerError.message}</p>
       )}
       ```

    **Step D — Remove duplicate checks from `superRefine`**
    1. Delete the entire `if (data.feeSchedulerMode === 'market-cap-based') { ... }` block (lines 99–106) and the entire `if (data.feeSchedulerMode === 'time-based') { ... }` block (lines 108–116) from `superRefine`.

Because the form uses `mode: "onBlur"`, empty required fields trigger base validation errors, which prevents `superRefine` from ever executing. The `useMemo` bypasses react-hook-form’s resolver entirely and displays errors based on watched values alone, matching the Phase 2 `priceError` fix.
