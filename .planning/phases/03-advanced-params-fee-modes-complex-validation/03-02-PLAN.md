# Plan 03-02: TokenLaunchForm — Holdback Slider, Quote Token, Fee Mode Selector, Red-Flag Warnings

## Objective

Extend `TokenLaunchForm.tsx` with three new form sections inside the existing "Advanced Options" / "Launch Parameters" card:
1. **Holdback Slider** — 0–100% with real-time percentage readout; red-flag warning at >10%
2. **Quote Token Select** — SOL (default) or USDC dropdown
3. **Fee Scheduler Mode Select** — Market-Cap Based (default), Time-Based, or Disabled (Fixed Fee)

Plus the **two-state red-flag warning visibility** (badge on collapsed header, alert banner inside expanded section) per FORM-05.

## Background

Phase 2 already added supply/price fields and established the `shouldUnregister: false` + CSS `hidden` collapsible pattern. The form uses ` react-hook-form` + `zodResolver` with a `TokenFormData` type from `types/token.ts`.

Key Phase 2 patterns to replicate:
- Card-based sections with `CardHeader` (clickable toggle) + `CardContent`
- `useMemo` for computed badge state (Modified badge)
- Per-field validation via Zod `superRefine` with `ctx.addIssue`
- Controller for custom input formatting (supply field)

Phase 3 decisions from CONTEXT.md:
- D-01/D-02: Holdback slider with numeric readout
- D-04–D-07: Red badge on header when collapsed + Alert banner when expanded, both at >10%
- D-15–D-18: Quote token dropdown with raw values; decimal math deferred
- D-08: Fee scheduler mode as Select with 3 options

    Critical: The red-flag warning must be visible even when the user has NOT interacted with other required fields (name, symbol, logo). Use the same useMemo-from-watch pattern that Phase 2 used for priceError (bypasses RHF resolver clearing).

  <acceptance_criteria>

    - Expanding the section shows an Alert banner with AlertTriangle icon and exact text: "Holding back more than 10% may be seen as a red flag by traders"
    - Reducing holdback to ≤10% removes the badge AND the Alert banner
