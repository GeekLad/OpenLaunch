        ```sql
        ALTER TABLE tokens ADD COLUMN holdback_percentage REAL NOT NULL DEFAULT 0;
        ```
     5. **Data migration for D-13 retroactive defaults on existing tokens:** Append to `0003_fee_configuration.sql` (after the 8 ALTER TABLE statements) an UPDATE statement that corrects the retroactive default per D-13:
        ```sql
        UPDATE tokens SET fee_scheduler_mode = 'time-based' WHERE fee_scheduler_mode = 'market-cap-based';
        ```
        This ensures existing tokens (which previously had no configurable fee scheduler and used time-based decay behavior) are marked with `'time-based'` rather than the new-token default `'market-cap-based'`. New inserts will still get `'market-cap-based'` from the schema `.default()` per D-15.
     6. Update `lib/db/migrations/meta/_journal.json` to include entries for 0002, 0003, and 0004 with:

       - `breakpoints`: true
       - `timestamp`: current Unix timestamp (use `date +%s`)
    
    Ensure the SQL syntax is valid SQLite ALTER TABLE. Each migration should be idempotent (safe to re-run on a fresh DB but adding NOT NULL DEFAULT on an existing column in SQLite is a no-op if the column already exists — which it won't on a fresh DB).

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-05 | Tampering | Malicious SQL in migration files | mitigate | Migrations only contain ALTER TABLE ADD COLUMN statements. No data manipulation, no DROP, no DELETE. All SQL is reviewed in this plan before execution. |
| T-01-06 | Denial of Service | Migration locks database during application startup | accept | SQLite ALTER TABLE is lightweight and runs quickly. The application already runs migrations at startup (via app/init.ts). Brief lock is acceptable for a single-node deployment. |
| T-01-07 | Information Disclosure | Default values leak business logic | accept | Default values are public form defaults, not secrets. No PII or credentials in defaults. |
</threat_model>
